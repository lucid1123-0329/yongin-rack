# 운영 배포 준비 현황

## 완료

- `yongin-rack-release`라는 별도 clasp 계정 연결로 배포 목록 조회 성공.
- 운영 배포는 버전 60. 서버 편집기의 HEAD와 운영 버전의 소스 SHA-256이 일치한다.
- 운영 소스는 리스킨 검증 기준 커밋의 Code.gs와 줄바꿈 정규화 후 동일하다. 운영 서버에만 있는 함수를 놓치지 않았음을 확인했다.
- 서버 백업은 저장소 외부에 보관했다. 비밀 값은 출력하거나 이 문서에 기록하지 않았다.
  - 운영 v60: `C:/Users/1230/Documents/yonginRack-backups/server-v60-7e527583e0e94b3da5b1c62da6328e72/`
  - 편집기 HEAD: `C:/Users/1230/Documents/yonginRack-backups/server-head-8a6c9d3da0fc4ad682da2c28ace5e2d1/`
  - clasp가 `.gs` 대신 `Code.js`로 저장한 것은 정상이다.
- `.claspignore`를 허용 목록 방식으로 바꿨다. `clasp show-file-status`에서 서버 업로드 대상으로 `Code.gs`와 `appsscript.json`만 표시된다.
- `tools/prepare-release.mjs`로 새 폴더에 홈페이지와 GAS 배포물을 분리한다. 기존 출력물을 덮어쓰거나 지우지 않는다.
- 검증을 통과한 배포물: `C:/Users/1230/Documents/yonginRack/.release/v70-NnWmWh/`
  - `site/`: 홈페이지 파일 82개와 `.nojekyll`. 서버 소스·문서·테스트·목업·비밀 파일 제외.
  - `gas/`: 서버 소스와 매니페스트 2개.
  - `release-manifest.json`: 파일별 크기·SHA-256 및 미배포 상태.
- 앞서 생성된 `v70-GB28MJ`는 자산 검사 보정 전 출력이므로 배포하지 않는다. 자동 삭제하지 않았다.
- 배포 준비 명령은 리스킨 검사와 보안/견적/문법/배포물 테스트가 실패하면 중단한다.
- 전체 테스트 14개 파일 및 리스킨 보호 검사 통과.
- 리스킨 검증 기준을 이동하는 main 대신 원본 커밋 `60ae8796960dcbb4628f4556ab5606decea0ab37`로 고정했다. 배포 후에도 같은 원본을 비교한다.
- 애플리케이션 파일은 이번 준비 단계에서 변경하지 않아 캐시 v70을 유지했다.

## 실행하지 않은 작업

- 커밋, 푸시, 브랜치 병합.
- clasp push / 배포 버전 갱신 / 기존 배포 삭제.
- PIN 초기화, 외부 키 재발급, 푸시 등록 변경.
- Google Sheets 데이터와 스크립트 속성의 백업/변경. 이번 백업은 서버 코드와 매니페스트만 포함한다.
- GitHub Pages 설정 변경. 현재는 main 루트에서 배포하는 방식이며 `.release/site`가 자동으로 사용되는 것은 아니다.

## 실제 적용 전 조건

1. 사용자의 커밋·푸시 및 운영 배포 승인.
2. Google Sheets의 견적/설정 데이터 별도 백업. 비밀 키는 채팅/공개 저장소에 넣지 않는다.
3. 홈페이지 배포 출력을 분리한 site 폴더로 전환할 방법 준비. GitHub Actions 방식이 적합하다. 전환 설정 자체는 아직 하지 않았다.
4. 소유자가 GAS 스크립트 속성에 새 `ADMIN_INITIAL_PIN` 설정. 값은 직접 입력하고 채팅에 공유하지 않는다.
5. 새 서버 소스를 업로드한 다음 PIN 초기화. 웹 배포를 갱신하기 전에 초기화를 마친다.
6. 서버와 홈페이지를 같은 전환 시간에 반영하고 익명 관리자 조회 차단, 로그인, 견적 공유를 검사한다.
7. 과거 취약 배포의 접근 차단과 외부 키 폐기/재발급, 실제 알림 테스트.

Git 원격 URL에 들어 있던 토큰은 앞선 준비 과정에서 URL에서 제거했다. 해당 토큰의 폐기/재발급은 별도로 필요하다. 비밀 패턴 검사는 보조 수단이며 모든 종류의 비밀 값을 찾아낸다고 보장하지 않는다.
