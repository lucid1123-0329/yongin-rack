# v70 1차 개선 적용 내역

2026-09-17. 기존 리스킨 작업을 보존하면서 보안, 견적 정확성, 고객 견적 화면을 우선 개선했다. 커밋·실제 배포·외부 키 재발급·실제 고객 데이터 변경은 하지 않았다.

## 적용한 내용

### 보안

- 관리자 조회를 인증된 POST로 전환. 기존 공개 GET의 설정·고객·견적·요청·단가 조회와 ID 기반 HTML 견적 조회를 차단했다.
- PIN은 서버 스크립트 속성에서 검증한다. 브라우저의 과거 PIN 해시·솔트를 제거하고 세션 토큰만 sessionStorage에 보관한다.
- 세션은 최대 6시간 유효하다. 서버 캐시가 먼저 사라지면 재로그인이 필요하다. PIN 교체는 기존 세션을 무효화한다.
- PIN 5회 오류 시 서버 전체에서 15분 잠금. GAS가 신뢰할 만한 호출자 IP를 제공하지 않아 기기별 제한은 아니다. 악의적인 잠금 유발과 4자리 PIN의 약점은 남으며, 향후 계정 기반 인증으로 전환하는 것이 좋다.
- 서버 최초 설정은 공개 웹 온보딩이 아니라 소유자의 GAS 편집기 작업으로 제한했다.
- 공개/관리자 설정 응답 모두 비밀 키를 제외한다. Gemini 키는 저장 여부만 표시한다.
- 푸시는 인증 후 서버에 등록한 구독 ID만 수신한다. 누구나 붙일 수 있는 `role=admin` 태그는 권한 근거로 사용하지 않는다. 잠금 화면 알림에는 고객 이름·전화·메모를 넣지 않는다.
- PIN·설정 저장 오류는 성공으로 처리하지 않는다.

### 견적 정확성

- 같은 초안의 저장 재시도·새로고침·중복 터치는 동일한 clientId를 사용한다.
- 서버가 이미 저장한 요청과 다른 내용이 같은 ID로 들어오면 덮어쓰거나 새 견적을 만들지 않고 충돌 안내를 표시한다. 견적 내역에서 원본을 확인하고 수정한다.
- 이전 견적을 새로 복사할 때 최신 단가표를 다시 읽고 변경 품목 수를 확인받는다. 누락/중복 매칭은 임의 선택하지 않는다.
- 직접 입력한 운송비·할인·선반 추가 등은 자동 가격 변환하지 않는다. 복사 안내에서 별도 확인을 요청한다.
- 기존 견적 수정에서는 계약 단가를 자동 변경하지 않는다. 현재 단가와 다르면 저장 전 경고한다.
- 일반 3축 규격은 W×D×H, 기존 일부 특수 랙의 D×W 및 높이/단수 형식은 유지한다. 기존 시트 데이터를 일괄 뒤집지 않는다.
- 고객 공유 데이터는 필요한 필드만 반환하며 내부 마진은 랙 단가에 배분한다. 수량으로 나누어떨어지지 않는 금액은 일부 수량의 단가를 1원 다르게 나누어 총액과 세액을 유지한다. 관리자 마진 숨김 미리보기도 같은 금액 보존 방식을 적용했다.
- 공유 토큰 생성 실패 시 안전하지 않은 ID형 링크로 대체하지 않는다. 공유 취소나 클립보드 복사만으로 요청을 발송 완료 처리하지 않는다.

### 고객 화면·기본 사용성

- 고객 견적에 휴대폰용 품목/공급가액/부가세/총액 요약을 추가했다. A4 렌더러 3개 본문은 유지했다.
- 이미지 저장 버튼을 축소된 A4 컨테이너 밖으로 옮겼다. 화면 폭/폰트/문서 크기가 바뀌면 문서 높이를 다시 계산한다.
- 없는 견적을 0원 문서로 표시하지 않는다. 만료 링크와 이전 ID형 링크에는 새 링크 요청 안내를 표시한다.
- 고객 요청 전화번호를 클라이언트와 서버에서 확인하고, 사진 개수/형식/크기를 제한했다. 손상된 사진과 처리 시간 초과는 오류로 종료한다.
- 무료 홍보 문구와 확인되지 않은 당일·하루 시공 약속을 랜딩/고객 페이지/블로그 문의 문구에서 제거했다.
- 공개 시공 사례 RSS의 문자열과 링크를 안전하게 처리한다.
- 관리자 견적 단계 이름을 보이게 하고, 직접 선택/이전 견적/음성 입력의 시작 버튼과 마지막 고객 확인 요약을 추가했다.
- 앱 모듈을 찾지 못할 때 반복 호출하던 음성/사전검사 보조 함수를 수정했다.

## 검증

- 기존 테스트 10개 파일 유지.
- 새 테스트: `security-regression.test.mjs`(10), `quote-integrity.test.mjs`(5), `script-syntax.test.mjs`(1).
- 실제 `Code.gs`, `api.js`, `auth.js`, `app.js`, `calc.js`, `estimate.js`를 가상 환경에서 실행해 인증·PIN 변경·만료·마진/세액·단가·저장 재시도를 검증한다.
- 서비스 15개 화면을 로컬 가상 데이터로 320px/1280px에서 확인했다. 고객 견적과 PIN 변경 등 핵심 흐름은 390px에서도 확인했다.
- PIN 실패 안내, 규격 입력 W900/D450/H1800, 없는 견적 오류, 만료 링크, 고객 요약, 저장 버튼 위치, 잘못된 전화번호 접수 차단을 브라우저에서 확인했다.
- 로컬 화면은 가상 API를 사용했다. 실제 GAS 배포, Google Sheets 권한, OneSignal 수신, iPhone PWA, 실제 음성 인식, 실제 이미지 다운로드 성공까지 검증한 것은 아니다.

## 검증 규칙 변경 범위

- 캐시 버전은 69 → 70으로 통일했다.
- `Code.gs`/`js/api.js`는 사용자 승인된 보안 개선 대상으로 변경 금지 대신 실행형 보안 회귀 테스트를 검증 스크립트에 연결했다.
- 기존 본문에서 `무료 견적 요청` → `견적 요청`만 정확한 예외로 허용했다.
- 공개 PIN 초기설정 경로와 URL의 hideMargin 신뢰 제거에 해당하는 두 토큰만 예외 처리했다.
- `js/calc.js`, `js/version-check.js`, 견적 렌더러 본문은 보호를 유지한다. SW는 캐시 이름과 프리캐시 목록만 수정했다.

## 배포 전 반드시 할 일 — 아직 실행하지 않음

1. 현재 GAS 버전/시트/작업 트리를 백업하고 전환 시간을 잡는다. 프런트와 서버의 인증 규약이 바뀌므로 한쪽만 배포하면 관리자 기능이 동작하지 않는다.
2. GAS 프로젝트에 새 Code.gs를 반영한다. 프로젝트 설정 → 스크립트 속성에 `ADMIN_INITIAL_PIN`으로 **기존과 다른 숫자 4자리**를 지정한다. PIN을 소스·문서·채팅에 남기지 않는다.
3. GAS 편집기에서 `initializeAdminPin`을 실행한다. 초기 PIN 속성은 실행 후 삭제되고 이전 세션/등록 알림 목록은 무효화된다. 이 함수는 기존 설정/견적 시트를 삭제하지 않는다.
4. GAS 웹 앱을 새 버전으로 갱신하고 예전 취약한 배포 URL도 비활성화한다. 익명 `getSettings`, `getEstimates`, `getRequests`, `viewEstimate`가 거부되는지 확인한다.
5. 같은 전환 작업에서 v70 프런트를 배포하고 새 PIN 로그인, 설정 저장, 견적 저장/공유를 확인한다. 단가 캐시가 남아 있다면 최신 목록을 다시 읽는다.
6. 노출 가능성이 있는 Gemini·OneSignal·Cloudflare·GitHub 토큰을 해당 계정에서 재발급하고 기존 키를 폐기한다. 현재 코드가 사용하는 서버 설정에도 새 값을 적용한다. 이전 시트의 pinHash/pinSalt는 더 이상 인증에 사용되지 않는다.
7. 관리자 기기에서 알림을 다시 등록하고 테스트 알림을 확인한다. 실제 수신과 등록 해제를 모두 검사한다.
8. 기존 `view.html?id=...` 고객 링크는 새 공유 링크로 재발급한다. 기존 유효 토큰 링크는 새 서버의 안전한 데이터 변환을 거친다.
9. 실패 시 구버전의 공개 고객정보 조회를 다시 열지 않는다. 관리자 사용을 일시 중단하고 서버/프런트 버전을 맞춘다.

## 다음 개선 묶음

- 실제 시공 사진 여부 확인 및 히어로 교체, 평당 대수 가정 검증.
- 시공 사례 초안의 실제 완료 여부/시공일 확인 단계. 현재 견적일 자동 채움과 완료 서술은 별도 보완 필요.
- 관리자 더보기/설정 정보 구조, 요청 목록 압축, 단가 관리 용어 정리, 로고·상호 최종 통일.
- 사진 업로드 압축/보관 정책과 관리자 포트폴리오의 공개 범위 정리. 요청 사진의 기존 Drive 링크 공개 방식은 이번에 바꾸지 않았다.
- 인쇄 서식의 고정 납기 문구는 보호된 렌더러에 남아 있다. 실제 업무 기준을 확인해 별도 수정해야 한다.
- 네이버/구글 검색 등록과 PWA 업데이트·오프라인·실기기 검증.

## 외부 API 설계 참고

푸시 대상 지정은 [OneSignal 메시지 API](https://documentation.onesignal.com/reference/create-message)의 구독 ID 지정 방식을 사용한다. 세션 캐시 최대 시간과 조기 제거 가능성은 [Apps Script Cache 문서](https://developers.google.com/apps-script/reference/cache/cache)에 따른다.
