# 관리자 검색 제외

## 코드 설정

관리자 11개 HTML, 루트의 이전 관리자 주소 10개, 고객 견적 확인 view.html에 noindex, nofollow가 이미 배포되어 있다. 사이트맵에는 공개 3개 주소만 포함한다. 메인 랜딩의 관리자 링크는 nofollow를 유지한다.

후속 수정: robots.txt의 관리자·이전 주소·view.html 수집 차단을 해제해 검색엔진이 noindex를 읽게 한다. robots.txt는 보안 장치가 아니며 기존 API 인증과 고객 견적 토큰 보호를 변경하지 않는다. 수정 파일은 커밋·배포 후 운영에 반영된다. HTML/JS 변경이 없어 PWA 캐시 버전 변경은 필요 없다.

## 구글 서치콘솔

1. 소유확인한 yongin-rack.com 속성 선택 → 삭제 → 임시 삭제 → 새 요청.
2. 관리자 주소가 이미 노출되어 빠른 제거가 필요하면 `https://yongin-rack.com/app/` 입력 후 ‘이 접두어가 포함된 모든 URL 삭제’ 선택. 루트 `https://yongin-rack.com/`는 절대 넣지 않는다. 공개 랜딩까지 사라진다.
3. 예전 관리자 주소가 검색되면 아래 URL 각각에 별도 요청한다. `.html` 접두어로 시작하는 URL 삭제는 해당 경로의 쿼리 변형도 포함하지만, `request.html`(고객 요청)과 `requests.html`(이전 관리자 요청 목록)을 혼동하지 않는다.
4. 임시 삭제는 약 6개월 유효한 신속 조치이며 영구 제외 정책은 noindex가 담당한다. URL 검사 → 실제 URL 테스트에서 noindex가 인식되는지 확인한다. 관리자 URL에 색인 생성 요청을 하는 목적은 아니다.
5. 페이지 색인 생성 보고서의 ‘noindex 태그에 의해 제외됨’은 관리자 페이지에서는 정상이다. 검색 제거 반영 시점은 보장되지 않는다.

## 네이버 서치어드바이저

1. 소유확인한 사이트 → 검증 → URL 검사/웹페이지 최적화에서 관리자 URL의 robots 메타 noindex 확인.
2. 요청 → 웹페이지 수집에서 이미 검색된 정확한 관리자 URL을 제출해 noindex 재확인을 유도한다. 검색 노출을 허용하는 것이 아니며 반복·대량 제출하지 않는다.
3. ‘요청 → 웹페이지 검색 제외’는 공식 안내상 삭제되어 404가 된 콘텐츠용이다. 현재 정상 사용하는 관리자 페이지를 그 메뉴 때문에 삭제하지 않는다. 사용 중인 페이지는 noindex 재수집 방식으로 제외한다.
4. 네이버 사이트 전체 제외는 사용하지 않는다. 공개 랜딩·고객 요청·시공 사례는 계속 노출 대상으로 유지한다.

## 한계 및 확인 범위

검색 제외는 인터넷 접근 차단과 다르다. URL을 아는 사람이 로그인 화면에 접근할 수는 있지만 인증 없이 관리자 데이터에 접근할 수 있어서는 안 된다. 이미 외부에 복사된 콘텐츠나 noindex를 따르지 않는 검색엔진까지 강제로 지울 수 없다. 서버 인증은 계속 필요하다.

콘솔 계정 내 삭제 요청을 대신 제출한 상태가 아니며, 실제 색인 여부는 소유확인 계정 보고서에서 확인해야 한다. HTTP 헤더 추가를 위해 Cloudflare 프록시나 DNS를 변경하지 않았다.
